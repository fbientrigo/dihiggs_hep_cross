# Canonical interface migration inventory

## Dependency graph before migration

```text
dihiggs.point.v2 / dihiggs_boundary output
  -> model_point_to_llp_recast_v1.yaml + src/llp_recast/data_contract.py
  -> legacy scripts and paper proxy tables
  -> MadGraph runner / sigma join
  -> Trackless response and downstream signal calculation
```

The repository also contained an additive `data_contract_v2.py` and
`model_point_to_llp_recast_v2.yaml`. They were not active consumers of the
v1 validator, so the migration promotes their richer semantics instead of
maintaining two runtime validators.

## Dependency graph after migration

```text
dihiggs.point.v2 / boundary enrichment
  -> canonical named model-point handoff
  -> canonical validator (one active path)
  -> point-specific UFO + MadGraph
  -> sigma_production_fb + sigma_source + sigma_provenance
  -> response consumer reads ctau_response_mm explicitly
  -> Trackless response / signal result
```

Frozen ATLAS response releases remain immutable evidence. Small active model
point artifacts must be regenerated by the producer before entering this
graph; no v1 compatibility adapter is provided.
